# 07：常见问题

## 401 Unauthorized

含义：平台没有接受 Key。

检查：

1. 是否把 `YOUR_API_KEY` 当成真实 Key。
2. Key 前后是否有空格、引号或换行。
3. 是否已经禁用/删除。
4. 是否错误使用网页登录密码。

## 403 Forbidden

Key 可能有效，但没有目标模型、端点、用户组或 IP 权限。检查 HrioAPI 的 Key 权限、账号分组、余额和白名单。

## 404 或 405

通常是 Base URL 多写或少写一层：

- 原始 API Base：`https://hrioapi.hrio.site/api`
- OpenAI SDK/Codex Responses Base：`https://hrioapi.hrio.site/api/v1`
- Chat 完整路径：`https://hrioapi.hrio.site/api/v1/chat/completions`

如果 CC Switch 会自动拼接 `/v1/chat/completions`，不要再把完整路径填进普通前缀框；除非开启“完整 URL 模式”。

## `/v1/models` 成功，但调用模型失败

可能原因：

- 模型只支持 Responses，却请求了 Chat。
- 模型只支持 Chat，却请求了 Responses。
- 使用的是展示名称，不是返回的 `id`。
- Key 能看见模型但没有调用权限或余额。

分别运行：

```powershell
python .\scripts\test_hrio.py --model "MODEL_ID" --endpoint chat
python .\scripts\test_hrio.py --model "MODEL_ID" --endpoint responses
```

## Codex 在 CC Switch 切换后仍用旧供应商

1. 退出 Codex。
2. 关闭启动 Codex 的旧终端。
3. 在 CC Switch 确认新卡片是“当前使用”。
4. Chat-only 方案确认本地路由和 Codex 接管都开启。
5. 打开新终端重新启动 Codex。

## 模型在 Codex `/model` 中不出现

Chat-only 本地路由方案需要在 CC Switch 的模型映射中添加真实模型 ID。修改后重启 Codex，`model_catalog_json` 通常在启动时加载。

## 视频生成一直没有 URL

先查看第一次响应是否是任务 ID/operation。异步视频模型需要查询状态，不要不断重新 POST 创建新视频。视频应使用更长超时，并关注平台账单。

## GitHub 泄露 Key 怎么办

立即吊销 Key，再创建新 Key。删除文件或强推 Git 历史不能保证旧 Key 没被爬虫、缓存或他人复制。

## CC Switch 数据在哪里

官方文档当前说明：

```text
~/.cc-switch/cc-switch.db
~/.cc-switch/settings.json
~/.cc-switch/backups/
~/.cc-switch/skills/
~/.cc-switch/skill-backups/
```

不要直接编辑 SQLite 数据库；使用 CC Switch 的导入导出和备份功能。
